# 盈亏分析历史行情（SQLite）

年度历史行情已改为优先读取本机 `simulation.sqlite3`，不再把新数据写入 localStorage。有效旧缓存首次读取时事务写入数据库，写入成功才删除旧键。持久化失败会明确报错，避免误认为已保存。

## 表与加载策略

- `analysis_daily_bars`：以证券、日期为主键保存不复权OHLCV、来源和获取时间；较旧响应不会覆盖新价格，部分刷新不会删除已有日线。
- `analysis_history_years`：证券、年份的年度元数据；每年包含上一年12月，以供年初收益基准。
- `analysis_suspensions`：有公开公告依据的停牌日及估值参考日期，独立于成交日线保存。分析时引用已知收盘价，绝不伪造停牌日成交行情。
- 页面只加载账本证券涉及的年份，已清仓证券不会继续索取清仓年份之后的数据，也不请求首次交易之前的年份。
- 完整往年缓存持续复用；当年跨上海日期后刷新，16:00后再次加载时更新当天盘中缓存。缓存失效后的网络请求仍以年度为单位。
- 同一证券、年份的进行中请求合并，最多3个并发。网络失败时可继续使用已保存的历史日线；显式“补充历史行情”会报告联网失败。
- 清理行情缓存会清理年度元数据和日线；已核验的停牌公告依据独立保留，账户数据不受影响。

## 逐笔成交后的持仓成本

全局历史成交与股票详情交易记录中的“持仓成本”均取该笔成交完成后的做T摊薄每股成本，与持仓列表的成本口径一致：本轮净投入（买入总支出、期初持仓投入减去卖出净回款，已包含历史手续费）除以剩余股数，显示四位小数。它不是 FIFO 剩余持仓成本，也不是用最新持仓成本回填旧记录。

- 成交后持仓为零时显示“—”；同日卖空后买回延续原轮净投入，日终清仓后跨日重新建仓重算。
- 净投入可能为负，按实际计算结果保留负成本。
- 成本按完整账本顺序回放后按成交编号关联。证券、日期筛选和列表倒序仅影响展示，不改变成本；编辑、删除成交后随账本重新计算，不向账户结构写入派生值。
- 股票详情费用列上行主显示费用合计，下行弱化显示佣金；合计包含佣金，费用来源可悬停查看。
- 股票详情类型简化为买入、部分卖出、做T、清仓、真清仓；期初持仓单独显示“期初”。当日持仓暂时归零显示清仓，日终归零显示真清仓；做T方向与部分配对信息保留在悬停说明中。

交易记录的时间列按日期、时间分两行显示，并按内容收窄列宽。股票详情中各持仓阶段默认展开，可点击带箭头的阶段标题独立收起或展开；折叠后保留该阶段的日期和收益汇总。阶段折叠状态按首笔成交编号关联，日期筛选不会丢失折叠入口或重置其状态。
