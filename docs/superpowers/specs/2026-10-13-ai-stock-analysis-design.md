# 个股与分组多模型 AI 分析：第一版设计

日期：2026-10-13

状态：待用户确认；本文仅定义设计，尚未实施。

适用产品：T刻桌面应用。

## 1. 目标与已确认决策

在现有看盘流程中，使用同一份公开市场资料让多个模型独立分析，再通过汇总模型整理多方结论。用户先看到综合总结，再逐条展开各模型给出的依据，能够查看分歧、追溯来源并回看历史。

已确认：

- 单股通过右键「AI 分析」进入右侧抽屉。
- 分组批量分析通过弹窗呈现。
- 主预测窗口为当前到今日收盘；同时分析未来 1～5 个交易日。
- 结合行情、资金流、新闻、公告，给出明确的逻辑依据。
- 使用用户自己的 API Key；设置中配置服务商、模型、密钥、自定义 API 地址。
- 支持多个模型配置，不限制配置数量；默认选择 2～3 个参与模型。
- 设置默认汇总模型，分析时允许临时切换；汇总模型可以同时参与独立分析。
- 各模型独立分析后，先汇总总结，再按关键结论展示不同模型的依据。
- 新闻和公告第一版使用无需额外付费的公开来源。
- 报告本地长期保存；支持历史回看、重新分析和重新汇总。
- 分析前显示预计模型调用次数。

本文中的具体限流、资料窗口和交互细节是供确认的设计默认值，不表示数据渠道已经验证可用。

## 2. 第一版范围与边界

包含模型设置、单股与分组入口、资料采集、独立分析、综合汇总、证据关联、本地历史、失败重试与取消。

复用应用当前支持的证券市场和代码范围，不扩展港股、美股。ETF 采用市场趋势、资金及基金公告等适用资料，不套用上市公司财务事件逻辑；资料不可用时明确标注。

暂缓：付费资讯接口、自动定时分析、消息提醒、账户成本与交易流水参与分析、自动交易、预测准确率统计、模型动态权重、报告跨设备同步、全文资料库。分析不改变账本、持仓、分组或交易记录。

## 3. 模型配置

### 3.1 配置项

每个配置具有独立标识，包括显示名称、服务商预设、自定义 API 基础地址、模型标识、密钥引用、启用状态。设置页支持新增、编辑、删除、测试连接，选择默认参与模型和默认汇总模型。

第一版支持 OpenAI 兼容的 Chat Completions 请求与响应格式。服务商预设负责填充基础地址；非兼容的厂商专用协议暂不适配。基础地址填写到 API 前缀，例如以 `/v1` 结尾的地址，应用追加 `/chat/completions`；明确提示用户不要填写完整调用端点。

不要求服务商支持 JSON Schema 或模型列表接口：模型标识可以手动输入，结构化报告通过约定 JSON、校验和显式格式修复重试实现。

### 3.2 配置与密钥管理

桌面密钥保存在系统安全存储，SQLite 只保存引用；输入框默认遮罩。安全存储失败时提示原因，不静默降级为明文保存。报告、日志和导出内容不包含密钥。

自定义地址由原生模型请求模块访问，不开放通用任意 URL 代理。默认使用 HTTPS，允许用户显式配置本机 localhost/回环地址的 HTTP 服务；其他明文 HTTP 地址第一版不支持。跨主机重定向不转发鉴权信息，错误信息脱敏。

「测试连接」执行一次小规模实际模型请求，界面提前标注可能产生调用费用，成功显示可用状态，失败区分连接、鉴权、模型不存在和协议不兼容。

删除或修改配置不改变历史报告中的模型身份快照。历史报告需要重新调用但原配置已不存在时，要求选择可用配置。

## 4. 数据来源与证据包

### 4.1 来源策略

| 数据 | 第一版策略 |
| --- | --- |
| 行情、分时、日 K | 复用现有行情与图表能力；保存来源、报价时间、采集时间和必要价格序列 |
| 资金流 | 复用现有东方财富资金流能力，保留统计口径与时间；不把供应商资金指标等同于全部真实资金交易 |
| 公告 | 优先评估巨潮资讯原始披露；交易所或东方财富公告索引作为候选补充入口，保存原始披露链接 |
| 新闻 | 优先评估东方财富公开个股资讯入口；保留原始媒体、来源链接与时间，第一版不纳入股吧和自媒体评论 |
| 大盘、板块 | 获取可用指数及已确认的板块映射；缺失时不臆造板块关系或板块强弱 |

公开页面存在不等于提供稳定或获准使用的程序接口。实施前必须验证候选渠道的获取方式、使用条件、字段、时效、覆盖、限流与失败表现。优先使用有明确支持的公开渠道；不能稳定获取或不能满足使用条件的来源禁用，并在报告中展示缺失。不能通过绕过访问限制解决渠道问题，也不能把不可用渠道包装成已接入。

来源参考：

- 巨潮资讯说明其为深交所信息披露官方网站：https://www.cninfo.com.cn/new/index?lang=zh
- 东方财富公开公告入口：https://data.eastmoney.com/notices
- 东方财富使用条件核验入口：https://about.eastmoney.com/home/protocol

### 4.2 采集窗口与处理

- 新闻默认最近 72 小时；近 7 天的重要持续事件可以补充，并标注旧事件背景。
- 公告默认最近 30 个自然日，优先筛选业绩、减持、回购、重大合同、重组、诉讼与风险提示等相关内容。
- 日 K 默认使用最近 120 个交易日，以实际可获取范围为准；不足时记录缺口。
- 最近 30 天之外的重要公告只有在本次实际获取并核验后才能引用，不能由模型记忆补充。
- 单股模型资料包默认最多纳入 20 条去重新闻和 20 份相关公告。超限优先保留近期、高相关原始资料，并标明筛选及省略数量；模型请求大小超限时不静默截断。
- 按证券代码与市场确认公告归属，新闻结合名称、实体和事件匹配；转载按事件去重。
- 公告读取相关正文或 PDF 文本。仅有标题、无法解析或扫描件无可用文本时，标注“仅标题”，不作正文事实判断；第一版不要求 OCR。
- 区分发布时间、事件发生时间、首次采集时间。来源只提供日期时保存时间精度，不虚构具体时刻。

### 4.3 同一资料快照

每次分析先确定数据截止时间，再采集和冻结证据包。实际获取时间和报价时间可以不同，但所有独立模型使用完全相同的冻结包。截止时间后的新闻、公告不进入本次判断；时间精度不足且无法确定是否在截止前可见的资料单独标注，不作为已确认催化。

程序计算指标，记录指标算法版本、价格复权口径及数据缺口；AI 负责综合推理，不负责猜测缺失数字。每条证据有稳定 ID、类型、来源、时间、实际使用内容和内容摘要校验值。报道事实、报道观点与公告披露事实分开标记。

模型不得自行联网扩充本轮资料，不得将资料中的文本当成系统指令，不得用训练记忆补造当前新闻。支持模型只能依据本轮资料包判断；来源引用必须能对应证据 ID。

## 5. 时间窗口与报告结构

### 5.1 预测定义

「当前到今日收盘」的方向以快照最新价为基准，判断今日剩余交易时段，而不是判断收盘相对昨收的涨跌。午休时以上午最后有效报价为基准，分析下午到收盘。

「未来 1～5 个交易日」从下一个交易日起算，以快照最新有效价为比较基准，同时呈现整体趋势与可能的阶段变化。两个窗口分别报告，不强行一致。

盘前近端窗口显示“今日开盘至收盘展望”，基准为最近有效收盘价；收盘后显示“当日复盘”，另给下一交易日展望。非交易日近端窗口显示“下一交易日展望”。日历使用中国市场交易日与 Asia/Shanghai 时区；无法核验日历时明确提示，不仅按工作日推算。

停牌证券不生成剩余时段的价格方向预测；未来窗口根据已知复牌信息给条件性分析，没有可核验信息则标注无法判断。关键行情缺失或明显过期时近端判断降为无法判断；程序记录新鲜度规则版本，第一版交易时段超过 2 分钟的报价标为延迟。

### 5.2 独立模型输出

每个时间窗口包含：

- 方向：偏强、震荡、偏弱或无法判断。
- 简短总结与推理依据。
- 支持证据、反向证据及证据 ID。
- 关键价位、计算依据、触发条件与失效条件；无数据依据的价位不得输出。
- 基准、偏强、偏弱情景；不适用或资料不足时说明原因。
- 风险、缺失资料及模型自述把握程度。

不输出未经校准的精确上涨概率，不把模型把握程度当成统计置信度。保留原始输出，同时校验股票身份、时间窗口、枚举、数值及引用。格式或引用不合格的报告标为无效，原文可查看但不进入有效共识统计。

### 5.3 综合输出与证据映射

默认先展示两个窗口的综合总结，然后展示关键结论、模型分歧和观察点。汇总模型使用同一证据包及有效的独立报告，形成独立的汇总调用；即使它参与了首轮，也不复用首轮响应冒充汇总。

每条关键结论有稳定 ID、时间窗口、综合解释、验证条件，以及各模型关联：支持、部分支持、反对、未提及。记录独立报告段落或结论 ID 和底层证据 ID。未提及不计为支持；同一配置的重试或多次版本不增加票数。

汇总的事实必须有证据支持，推论必须标注为综合推断并附依据。程序验证模型引用与证据引用真实存在；不支持的汇总内容不能作为有效结论展示。模型共识程度与数据完整程度分别呈现，不把多模型一致当成事实正确的保证。只有一个有效模型时显示“单模型结果”，不得宣称多方共识。

## 6. 单股右侧抽屉

单股右键菜单新增「AI 分析」。右键目标始终是该行证券，不因已有多选改变单股对象。

抽屉结构：

1. 顶部：名称、代码、报告时间、数据截止时间、状态和关闭入口。
2. 分析配置区：参与模型、汇总模型、预计调用次数和开始按钮；记住上次选择，首次采用默认配置。
3. 综合总结：两个时间窗口的结论、共识程度与数据完整程度。
4. 关键结论卡片：展开后查看各模型观点、理由、数据及来源链接。
5. 分歧与观察点：解释冲突来自哪些证据或推理权重，以及如何验证。
6. 详情区：各模型原始报告、全部使用资料、历史记录。

打开时优先显示已有最新报告并提示其时间；没有报告时显示配置与空状态，不自动发起付费模型调用。生成中展示采集和各模型进度，已完成独立结果可先看。切换股票或关闭抽屉不会静默取消任务，后台任务状态可再次打开查看；取消使用显式按钮。

## 7. 分组批量弹窗

分组工具栏新增「AI 分析本组」。配置区明确当前分组、成员数，默认分析全部分组成员，不随表格搜索或筛选静默缩小范围；允许切换为已勾选范围。启动后冻结成员快照。

弹窗上方显示总体进度、完成覆盖数量及分组总结。下方表格按股票展示两个窗口方向、核心依据、主要风险、分歧与状态。展开个股后呈现与单股抽屉相同的关键结论和模型证据。

逐只完成逐只显示，失败证券单独重试。分组总结读取本次个股综合报告及其引用，避免跨股票混淆证据。部分个股没有综合报告时列明遗漏，不凭独立报告静默补齐。若无有效个股综合报告，则不生成分组总结。

关闭弹窗与取消任务分开；重新打开可查看进度。分组成员后续变化不影响本次任务和历史报告。

## 8. 调用次数、并发与成本

预计模型调用次数：

- 单股：M + 1，M 为参与独立分析的模型配置数量。
- 批量：N × (M + 1) + 1，N 为股票数量，最后一次用于分组总结。
- 例如 3 个模型分析 10 只股票，预计 41 次；汇总模型是否参与首轮不改变公式。
- 单股重新汇总通常 1 次；批量仅重新生成分组总结为 1 次，重新汇总所有个股再生成分组总结为 N + 1 次。

预计次数不包含资料请求、连接测试、失败重试或格式修复；这些另行计数。配置模型数量不限制，执行采用队列，全局默认最多 3 个模型请求并发，同一 API 地址默认最多 2 个。请求超时默认 120 秒。

瞬时连接错误、限流和 5xx 默认至多自动重试一次，遵循可用的 Retry-After；鉴权、模型标识和协议错误不自动重试。格式修复最多另调用一次，并在进度与实际次数中列明，不隐藏额外调用。

超大资料包在调用前提示无法发送或调整资料范围；第一版不静默拆成无限额外模型调用。输入/输出 token 用量仅在服务商实际返回时保存；不把请求次数等同于金额，不在未知费率下估算费用。

## 9. 本地保存与版本

### 9.1 存储边界

沿用桌面 SQLite 数据库，为 AI 独立新增表，不把报告塞进账户 payload。模型密钥单独保存在系统安全存储。第一版完整运行面向桌面；浏览器开发预览使用模拟数据，不持久化真实密钥。

逻辑实体包括：模型配置、分析任务、资料快照、证据、模型调用与报告、综合报告版本、关键结论与证据映射、批量任务与成员关联。大体积必要快照可存于应用数据目录，数据库保存索引及校验值；写入和删除保证引用一致。

### 9.2 保存规则

任务创建和每个模型完成后及时保存，不等全部结束才写入。报告保存股票与分组身份快照、截止时间、资料包、模型身份快照、分析规则版本、原始输出、结构化输出、汇总版本、实际调用数、错误及完成状态。

必要摘录长期保存，新闻原始全文不默认归档；公告保存实际使用段落、标题、来源和原文链接，不默认长期保存所有 PDF。保存的是本轮实际分析输入，来源页面以后变更或失效不改变报告证据。

临时下载文件与未被报告引用的采集缓存可以清理；历史报告引用的指标、价格序列及证据不能随缓存过期删除。报告长期保留，支持显式删除；第一版不自动按时间删除报告。

### 9.3 历史操作

- 历史回看：按股票、日期和任务状态查找，显示时间窗口摘要及模型数量；批量个股结果也能从股票历史找到。
- 重新分析：获取新数据，建立新任务和快照，保留旧报告。
- 重新汇总：使用指定历史快照及已保存的有效模型报告，生成新汇总版本；不补入最新新闻，不修改原预测时间。
- 模型失败重试：沿用冻结快照，新增调用尝试，保留旧失败记录；数据已过时则提示可另发起重新分析。
- 成功模型重新运行：第一版通过重新分析完成，避免在历史任务内悄悄替换有效结果。
- 批量个股重试或重新汇总后，分组总结明确标记版本过时，用户可单独重新生成。
- 删除报告：单股或批量任务作为明确删除对象；批量中的个股报告默认随批量任务管理，确认界面解释影响范围，共享资料仅在无引用后清理。

第一版不新增收藏与导出功能；后续可添加，不影响本地长期保存。

## 10. 异常与生命周期

任务状态：待采集、采集中、独立分析中、汇总中、完成、部分完成、失败、取消、中断。子任务状态分别保存。

- 来源获取失败与成功但无相关内容分别记录。关键价格资料不满足预测条件时显示无法判断，仍可保存事件分析。
- 部分模型失败时基于有效报告汇总，并标注覆盖；全部失败时跳过汇总。
- 汇总失败或校验失败时原始模型报告仍可查看，允许重新汇总。
- 取消停止排队和后续汇总，尽力中止在途请求，保留完成结果；已发送请求仍可能被服务商计费。
- 应用退出或崩溃后任务标记中断；重启不自动继续发起模型付费调用，用户选择重试或重新分析。
- 任务去重与事务写入防止双击创建重复任务；不同任务不共享模型对话上下文。
- 错误提供可操作原因，日志不暴露密钥、鉴权头和无关账户资料。

## 11. 模块划分与现有代码结合

| 模块 | 职责 |
| --- | --- |
| 资料采集与规范化 | 复用行情、图表、资金流；新增新闻、公告适配器；去重、时间过滤和来源状态 |
| 证据快照与指标 | 生成固定资料包、计算指标、分配证据 ID，保存新鲜度和复权口径 |
| 模型网关 | 读取安全存储密钥，调用兼容接口，限流、超时、重试、错误脱敏 |
| 任务编排 | 单股与批量队列、取消、阶段状态、调用计数 |
| 报告校验与汇总 | 校验独立输出、整合结论、验证来源映射与汇总版本 |
| 本地报告仓储 | SQLite 迁移、任务与报告持久化、历史查询、删除与清理 |
| Vue 界面 | 模型设置、单股抽屉、批量弹窗、证据展开和历史回看 |

现有入口主要位于 `src/TradingDesk.vue`，右键组件为 `src/components/RowContextMenu.vue`；新功能使用独立组件和服务，避免继续堆积在主页面。行情参考 `src/quotes.ts`，原生资金流参考 `src-tauri/src/fund_flows.rs`，存储参考 `src-tauri/src/storage.rs`。分析请求通过原生层执行，避免浏览器 CORS 和前端暴露持久密钥。

## 12. 验收标准

1. 可以配置多个兼容模型与自定义地址，测试连接并选择默认模型；密钥不出现在数据库明文字段、报告或日志。
2. 单股打开右侧抽屉，批量打开弹窗；启动前看到范围、参与模型、汇总模型和正确预计次数。
3. 所有独立模型使用同一快照，首轮看不到其他模型报告。
4. 两个时间窗口基准明确，盘前、午休、收盘、非交易日和停牌行为符合本文。
5. 新闻与公告关联正确、去重、标时；来源失败和无内容可区分；公告正文不可得时不伪造内容。
6. 综合结论可以展开模型立场、对应理由及证据；错误引用、未提及和反对不能被当成支持。
7. 模型或资料部分失败仍能展示可用结果；重试、取消与中断行为可验证。
8. 重启后可完整恢复历史报告；重新分析和重新汇总保留旧版本及原始时间。
9. 分组成员调整不改写历史范围；批量总结引用可追溯到具体个股及版本。
10. 模型调用次数与重试记录一致；队列不随配置数量失控。
11. SQLite 迁移与新模块不影响账户、交易、行情刷新和现有右键操作。

验证使用固定模拟行情、新闻、公告及模型响应覆盖主要流程、错误引用、时间边界和持久化；对候选公开来源及自定义模型接口进行小规模集成验证。无需用真实股票方向作为功能测试通过条件。

## 13. 设计确认与下一阶段

本文确认后再编写实施计划，细化来源验证、存储迁移、接口契约、界面与测试任务。来源验证应作为前置阶段：若候选渠道无法满足免费、稳定、可追溯的目标，先报告实际限制并调整来源方案，不宣称完整新闻/公告能力已具备。

建议实施顺序：公开来源验证 → 模型设置与网关 → 单股闭环和历史 → 多模型证据汇总 → 批量弹窗及分组总结 → 集成验收。所有阶段沿用同一份设计，不提前扩展后续功能。
