## 阅读目标与界面结构

用户应先知道现在适合采取什么动作、哪些动作暂不适用，然后了解依据。保留证券分析抽屉，桌面宽度建议 900～1040px，窄窗口使用单列。采用现有应用的冷白、灰蓝与克制蓝色；红绿只表达涨跌，建议状态用文字和蓝/橙标签，不用红绿误导买卖。

1. 固定顶部：证券、报告截止时间、历史版本、删除、关闭。
2. 一句话判断：当前首选动作、最重要约束、影响操作的数据缺口。
3. 账户依据条：持仓/可卖数量、FIFO 均价、摊薄成本、本股市值、本机账本余额、资金质量。
4. 五类建议：每项直接展示动作、简短原因、触发条件、停止条件；数量与资金依据在首屏保留摘要。
5. 每项展开：费用影响、关联交易、逐模型依据与分歧、证据引用。
6. 底部辅助区：模型与资料、历史/回收站、资料来源、执行记录，完成后默认折叠。运行中展开执行进度；配置在开始后自动收起。

首选动作是五类建议之间的优先级归纳，不能用一句“建议买入”隐藏时间、可卖数量或数据缺口。单模型明确“单模型依据”；不能标为多模型共识。结构与引用通过也不等于建议获利或事实全部正确。

## 五类操作建议

| 模块 | 回答的问题 | 时间范围与专属依据 |
| --- | --- | --- |
| 今日 / 下一交易日准备 | 现在是否行动，哪些条件满足才行动？ | 盘前准备、盘中剩余时段、收盘后复盘及下一交易日准备；休市不预测当天收盘。使用实时程度、价位位置、可卖数量与今日成交。 |
| 本周操作 | 本周还剩哪些机会和风险，仓位如何管理？ | 截止时点之后的本周剩余交易日；周五收盘后标为本周复盘，下一周准备单列。不能把未来五日当作本周。 |
| 稳健方案 | 如何保护已有持仓、减少无依据的操作？ | 持仓风险、可卖约束、成本差异、持仓集中度（仅在已有本地汇总且用户允许发送时）。默认给出不操作条件。 |
| 短期 / 做 T | 短线条件是否成立，价差能否覆盖费用？ | 短期 1～5 个交易日；做 T 为本模块的条件分支，明确底仓/可卖数量、T+1、买回资金及费用。不是另加一条必须执行的命令。 |
| 中长期 | 1～3 个月是否有足够资料支持持有或调整？ | 需基本面、公告正文与足够历史；当前近 60 日日线不能单独支撑中长期基本面判断。不足时输出“暂不形成中长期操作结论”，并列需要的资料。 |

所有模块都存在，不适用时输出等待或资料不足及原因。时间范围和操作风格是两个维度：今日/本周的动作可能采用稳健或做 T 方式，不能机械生成五条互相冲突的买卖指令。每项补充优先级、与其他方案的互斥条件、适用用户状态。未持仓时稳健模块转换为入场纪律，做 T 标为无底仓不适用。

每条建议至少包含：`type`（固定枚举）、`status`（actionable/conditional/wait/insufficient/notApplicable）、`action`、`reason`、`horizon`（明确起止或资料不足）、`trigger`、`invalidation`、`quantityBasis`、`cashBasis`、`feeImpact`、`evidenceIds`、`conflictsWith`。不要求模型提供没有测算依据的股数、目标价或概率。用户没有要求自动下单，本功能保持研究建议。

建议枚举：`today`、`week`、`conservative`、`shortTerm`、`mediumLongTerm`。短期模块可增加 `intraday` 子方案。模型缺项时一次针对性修复，仍失败则标为无效，不能由前端补造建议。

## 持仓、交易与资金的数据口径

### 同一截止时间

点击开始时冻结 `asOf`。账户成交和资金流水同时过滤到该时点，再调用现有 `replay`；不得用最新余额配旧交易/旧报告。行情仍保留自己的时间和延迟状态。历史重新汇总使用原快照，只有重新分析才更新数据。

### 本股持仓与交易

复用 `src/ai/positionContext.ts` 与 `src/sim/tradeStages.ts`。本轮以日终清仓为边界，同一天清仓又买回仍属于同一轮。发送当前持仓、可卖数量、FIFO 成本及均价、净投入及摊薄成本、交易制度、费率确认状态与本轮成交。近期成交默认展示本轮最近 10 笔，模型仍使用已确认发送范围内的完整本轮记录；旧轮交易仅在后续明确扩展时纳入。

FIFO 均价回答现存批次成本，摊薄成本含本轮已卖出回款，两者不能互相替代。今日买入的 T+1 数量不能当作可卖底仓。成交价不是未来触发价的充分依据。

### 本机账本余额

取过滤后的账户 `replay(...).cash`，与状态栏/账本口径一致，不手动填券商余额、不接券商接口。另存 `asOf`、`source=localLedger`、账本已初始化状态、余额是否负数和相关资金异常。模型只收到余额及质量摘要，不附带其他证券成交明细或完整资金出入记录。

界面统一写“本机账本余额”，tooltip 解释它来自期初资金、成交收支与资金流水，不等于已核验的券商实时可用资金。余额缺失、负数、账本未初始化或存在尚未核实的资金异常时，明确“买入能力待核实”；不能使用负数作为可投入金额，也不能仅因正数就建议耗尽余额。以余额为上限只能说明账本资金约束，不能证明券商一定可成交。

资金作为独立 `cash` 证据冻结，账户摘要作为 `accountContext`；结构按版本校验。即使未持仓，用户确认包含账户依据时也可发送余额摘要，持仓为 null。默认沿用分析前资料范围确认，并直接说明“本股持仓、本轮交易、本机账本余额将发送给选定模型”；取消账户资料后不能推断用户持仓或资金。

### 引用要求

持仓相关结论必须引用本股 position；资金能力结论引用 cash；交易归因引用本轮交易证据或 position 中可定位的交易 ID；价格条件引用行情或日线。汇总按同类操作建议引用独立模型原文，并保留资金限制、停止条件与费用缺口。支持字段不能引用别的策略或别股记录。数据不足应降低结论强度，不能隐藏在 tooltip。

## 展开与 tooltip 的分工

| 直接展示 | 折叠展开 | Tooltip |
| --- | --- | --- |
| 首选动作、五类建议、触发/停止条件、数量/资金摘要、阻断操作的数据缺口、模型分歧摘要 | 每类模型原文/引用、本轮交易表、费用明细、完整报告、数据来源、完成后的日志 | FIFO/摊薄成本解释、账本余额计算口径、置信等级定义、引用校验含义、重新分析与重新汇总区别 |

tooltip 支持悬停、聚焦、Esc，鼠标进入提示内容保持显示；Esc 优先关闭提示，不误关抽屉。正文关键条件不依赖 tooltip。折叠标题显示条数或结论摘要，展开状态只属于当前报告，切换报告不能沿用上一份交易数据。

## 报告删除与回收站

在报告顶部和历史列表提供删除入口，点击后确认明确证券、报告日期与影响范围。默认移入回收站，保留快照、独立报告、所有汇总版本、引用资料和执行记录；可以恢复，不影响账户成交和模型配置。回收站不自动到期清空。永久删除单独确认，写明不可恢复，只清理本任务拥有且未被其他任务引用的资料。

运行中任务不能删除：先明确取消并等待任务终止；删除不能悄悄触发取消。数据库新增软删除标记与时间，正常历史查询排除软删除项；回收站单独分页查询。若报告属于批量任务，第一阶段以父任务整体为删除单位，确认弹窗标明成员数；不单删子报告破坏分组引用。恢复应恢复整批。

预览中的删除/恢复只改变虚构页面状态，不读写真实报告。实际回收站后端尚未实现。

现有 V1 报告继续按原来的稳健/做 T/中短线展示，标识“旧版报告，未包含资金依据”。不把旧版中短线换标题伪装成 1～3 个月。V2 添加 `reportVersion` 与操作模块，在数据库采用兼容的新 JSON 内容/版本字段；新增资金上下文允许旧请求缺省。

目前格式修复独立交付：统一初始提示与完整三策略示例；修复提示携带具体校验错误和完整结构；titleOnly 不可作为实质依据；零有效报告记失败，原始无效输出仍可追溯。一次格式修复不保证所有模型都能成功。没有重新调用真实模型，不能声称 MiMo 线上联调已通过。

后续顺序：账户资金快照与契约 → 五类独立报告和汇总校验 → 实际报告布局 → 删除/恢复仓储 → 集成验收。分组批量分析沿用原实施计划，属于后续工作，不混入本次设计预览交付。

## 验收清单

- 五类建议均有动作或明确降级，今日/本周按上海时间和交易日历计算，收盘/周末边界准确。
- 持仓、成交、现金冻结到同一时点，费用、T+1 与可卖数量被尊重；负余额与缺资金记录不能输出可执行加仓建议。
- 未持仓、未授权账户资料、单模型、缺基本面、无有效报告都有清晰状态。
- 旧报告不伪装含资金或中长期判断；重新汇总保持原快照。
- 删除/恢复、运行中禁删、永久删除、共享引用与批量影响范围经过数据库测试。
- 首屏能读到五类动作与主要约束，模型长文本按需展开；键盘可用，窄屏无横向溢出。
- 实网模型联调仅在明确调用预估并得到相应授权后进行；模拟预览不作为真实分析结果。
