# 0.9.6：DeepSeek 兼容与等待原因说明

支持 DeepSeek 服务商及 deepseek-flash、deepseek-v4-pro 预设，仍可手动填写模型名称。

## 请求与超时

- DeepSeek、MiMo 的分析、汇总、格式修复及连接测试明确发送 `thinking: {type: disabled}`。其他兼容接口不擅自添加服务商专用参数。
- DeepSeek 报告使用原生 JSON 输出约束。
- 连接等待、响应头等待和完整报告等待分别处理。DeepSeek 报告最多等待 660 秒取得首段实际内容，之后最多 300 秒接收完整数据；连续空行不刷新期限，可随时取消。
- 已收到成功响应头后，超时、断流或空回应不会自动重发请求。提示区分未收到内容、仅收到保活空行、已收到部分报告，并说明下一步。
- 关闭思考不代表排队或网络等待一定消失。本机没有配置 DeepSeek，此次未调用真实模型，不能确认另一台机器的实际超时根因。

## 做 T 等待原因

行情时间不符合要求或没有通过费用、资金和股数检查的组合时，显示正常等待原因，不混同接口失败。保留行情时效、底仓、可卖股数、资金和整手校验。做 T 比例 100% 是比例上限，仍受底仓等限制，不表示必须卖出全部持仓。显示行情更新时间及刷新后重新分析的处理方式；旧报告中的内部字段也转换成普通中文，原始报告仍保留。

## 离线验证

覆盖关闭思考请求、原生 JSON、服务商识别、空行保活、首次内容等待、保活超时不延长、部分报告断流不重发，以及过期行情与做 T 上限。全部使用模拟 HTTP 服务，未消耗真实模型额度。

## 官方依据

- [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)：默认启用思考，支持明确关闭。
- [DeepSeek 限速与保活](https://api-docs.deepseek.com/zh-cn/quick_start/rate_limit/)：非流式返回保活空行，推理十分钟未开始时关闭连接。
- [DeepSeek JSON 输出](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)：原生 JSON 参数及空输出可能性。
