# 个股 AI 分析 · 0.9.4

入口：自选与持仓 → 个股右键 → AI 分析。先在设置中保存兼容模型配置；开始前选择独立模型和汇总模型，界面显示预计调用数。第一次生成会调用模型，历史回看、删除、恢复不会调用模型。

## 五类建议

报告先显示具体价格与股数的条件预案，再通过标签切换今日、本周、稳健、短期/做 T、1～3个月中长期五类建议。账户依据、原因、触发/停止条件、逐模型原文与执行记录默认折叠，预案的成交依赖和停止条件直接显示。模型与资料位于辅助区，开始后自动折叠。

盘中今日建议只覆盖剩余时段；收盘后复盘并准备下一交易日。本周只使用本周剩余交易日，周五收盘和周末按复盘处理。中长期当前缺少已核验财报/公告正文时明确资料不足，不用短期行情冒充基本面。等待或不操作也是有效建议。

## 账户资料与资金

默认包含本股持仓、可卖数量、FIFO 均价、摊薄成本、本轮成交的时间/方向/数量/价格/费用/备注，以及本机账本余额和质量摘要。它们冻结到同一截止时间；未持仓也可提供本机余额，不能假设底仓。取消账户资料选项后不发送持仓、交易或余额。

本轮沿用日终清仓口径，同一天清仓又买回仍属于同一轮。金额复用账本 replay，FIFO 均价不等于摊薄成本。余额来自本机期初资金、成交与资金流水，未经券商实时资金核验。未初始化、负余额或资金异常时不形成具体买卖步骤。直接加仓需现款足额；账本余额为零仍可评估先卖后买，但卖出回款必须足够覆盖最高买回价含费用。盘中可卖为零不能做T；收盘后的下一交易日预案仅估算已交收可卖数量，执行前核对券商。费率或交易制度未确认时不能把做 T 标为可执行。

以上允许的资料会发送给本次选择的独立及汇总模型，冻结报告保存在本机。不会附带其他证券的成交明细、完整账户资金流水或模型密钥。新闻仅提供来源链接和手工资料；公告仅标题/链接，不能作为已读取正文的依据。

旧版报告保持原三策略展示，明确没有本机余额依据。重新分析创建新快照和五类建议；重新汇总使用原快照和原报告，不能更新持仓或补造中长期资料。

## 删除、回收站与恢复

打开报告后点击“删除报告”，确认后移入回收站，连同独立输出、全部汇总版本和引用资料保留。抽屉顶部“回收站”可以恢复或单独确认永久删除；回收站不自动清空。恢复后可立即查看原报告，无需模型调用。

正在运行的任务不允许删除，取消后也要等待原生 worker 完全结束。批量子报告只能通过整批根任务管理。永久删除不可恢复，只清理不再被其他任务引用的快照/资料；账户成交、模型配置和其他报告不受影响。历史及回收站支持加载更多。

## 0.9.1 请求与校验修复

五类建议改为固定 operations 对象：today、week、conservative、shortTerm、mediumLongTerm 必须全部存在且不得额外增加模块。应用只分配模块标识，继续校验模型提供的动作、条件、证据和账户限制；缺项不补造建议。MiMo 已文档化的型号启用原生 JSON 模式，它保证 JSON 格式，不保证五类业务字段完整；其他兼容接口不添加未经确认的参数。

请求资料仅保留一份 evidence，移除重复的 series/indicators；行情重复列名改为 columns/rows 表格。持仓、本轮交易和本机余额内容完整保留，存储的原快照不变。本机已保存失败样本的快照请求资料从34415字节降为12667字节，减少63.2%；这不是实测token或模型耗时下降比例。格式修复请求只带一份原系统约束、一份资料和上次输出，并关闭额外思考，最多修复一次。

连接超时15秒（含TLS握手）；发出请求后60秒未收到响应头，报告“等待接口响应超时”；收到响应头后允许300秒生成/接收完整报告，报告“等待生成超时”。界面分别显示发送、接口已响应及完整响应已接收。响应头/正文超时不自动重复调用；网络连接失败或429/5xx保留至多一次重试，格式修复不做额外重试。等待响应头超时不能确认服务端是否已开始处理。模型返回finish_reason=length的截断输出不得作为有效报告。

验证：509项前端测试、93项Rust测试通过；8项默认跳过（实网/系统密钥库及只读样本诊断），只读样本诊断另行运行通过；类型检查、生产构建、Rust/修改前端文件格式检查通过。所有模型请求测试均为本地模拟服务，未调用真实模型。独立代码审查没有发现严重问题。

MiMo JSON模式依据：[官方结构化输出文档](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/text-generation/structured-output)。

## 0.9.2 普通结论结构与原文审计

普通claims每项必须有报告内唯一非空id（最多80 UTF-8字节）、非空text（最多6000 UTF-8字节）和1～30个允许的evidenceIds。提示与示例明确给出完整结构；operations不输出id的规则只适用于五类模块，不适用于普通结论。格式修复按具体validationError路径处理，不能只检查operations。应用仍严格拒绝缺少普通结论标识，不自动补ID或建议。

文字校验现在区分缺字段、错误类型、空文字与超长，并标出claims[0].id、windows[0].logic或operations.today.reason等具体路径；超长显示实际UTF-8字节数和上限，资料引用及重复结论标识也显示路径。

独立报告新增outputs审计数组，分别保留首次和收到的格式修复原文、各自校验结果、finishReason、usage和attempts；rawOutput仍为最终响应，兼容原展示与旧报告。没有收到修复响应时不伪造原文。界面逐次展开“首次输出”和“格式修复输出”，旧报告继续展示原始rawOutput。旧版曾被覆盖的首次原文无法恢复。汇总只接收有效报告的windows与claims，不发送这些审计原文。

此次使用已保存的失败输出离线回放：原文准确拒绝claims[0].id；仅在测试内加入5个普通结论ID后，通过全部结构、证据引用、时段、持仓与余额校验，未改动建议内容或用户数据库。该私人样本未写入项目。510项前端测试、95项Rust测试通过，9项默认跳过（包含2项本机诊断）；保存输出回放另行通过。类型检查、生产构建、格式检查和独立审查通过；没有调用真实模型。

## 0.9.3 引用协议及真实模型验证

所有五类模块（包括等待、资料不足、不买入）必须引用本次授权提供的position/cash资料；请求明确提供allowedEvidenceIds、requiredOperationEvidenceIds及逐资料referenceAllowed。仅标题公告不能进入evidenceIds，包括资料缺口说明；可以在文字中说明缺少正文。校验一次集中报告所有引用错误及其路径，不自动补引用。

模型请求使用E1/E2等资料短编号，汇总使用R1/R2等报告短编号；应用仅按本次快照或报告列表精确还原真实ID。未知编号、其他资料ID及titleOnly仍拒绝，存储和引用查看使用原ID，原文保留模型返回的短编号。汇总只提供五类操作结论作为支持候选，每类每个报告至多引用一条同类结论，不能追加普通趋势/资金结论冒充同类支持；支持错误显示具体keyClaims路径。

V2 MiMo输出请求提供完整函数参数schema（return_stock_report/return_stock_summary），五类模块、普通结论及引用字段均列为必填或枚举；仅使用官方支持的tool_choice=auto，工具参数只作为报告数据解析。只接受一个匹配名字的函数调用，未知或多个调用拒绝；正文回退仍须通过全部本地校验。工具模式按官方FAQ建议关闭额外思考，报告正文依然必须提供原因、条件和证据。不能把工具schema当成无需校验的服务端严格保证。其他兼容服务和旧版三策略报告保持原JSON输出协议。

接口空正文错误现在包含finish_reason与completion/reasoning token数；仍不自动重发。没有提高8192生成上限或改变15/60/300秒超时。

真实验证经用户明确授权，使用只读数据库里的同一失败快照和已配置Flash/Pro，通过生产Gateway、请求及校验代码执行。诊断期间共12次真实请求：曾发现一次接口无正文（原日志未保留结束原因，未断言其根因）、UUID抄错、普通结论被用于汇总支持、JSON遗漏模块等失败；这些不能算通过。最终工具协议连续两轮共4次调用全部一次通过，无重试/格式修复：Flash58.8秒、Pro21.9秒；Flash55.8秒、Pro23.7秒。各次reasoning_tokens为0。QA原文只保存在本机私人临时目录，不写正式报告数据库，不记录密钥。

最终验证：510项前端、100项Rust测试通过，11项默认跳过；两份真实引用失败输出离线回放及明确授权的真实模型测试另行通过。类型检查、构建、格式与独立审查通过。旧报告、回收站、恢复及账户业务校验保留。

依据：[MiMo函数调用参数](https://mimo.mi.com/docs/en-US/api/chat)、[工具调用思考模式说明](https://mimo.mi.com/docs/en-US/quick-start/faq/api-integration)。


## 0.9.4 具体操作预案与结论优先展示

默认偏好“保留底仓，优先做T”；设置中可调整偏好、保留比例（默认50%）及单轮比例上限（默认25%）。数量向下取整到本账本支持的整百股；低于最小申报量就等待，不为凑一手而突破比例。科创板预案最低200股且采用整百股子集；未知规则、零股处置、未确认费率或异常账户不硬给股数。

应用从当前未复权报价、前一交易日和近5/20日高低点建立冻结价位编号；摊薄成本标明只是成本参考，不能冒充技术支撑。先筛选最多三组已覆盖双向费用、底仓和资金约束的做T候选。模型选择其中一个完整组合并判断触发/取消条件，不扩大买回区间、不改股数；减仓、加仓仍分别检查可卖底仓与现款上限。价位是观察锚点，不是保证到达的预测。

费用采用与账本一致的逐笔成交额、最低佣金、卖出印花税与双向过户费口径，以十进制计算和半入舍入到分。先卖后买采用最低卖出回款与最高买回成本校验；买回必须等待先卖成交及券商可用回款确认。T+1买回不增加当日可卖数量。界面分开显示只成交卖出腿的余额、持仓和剩余摊薄成本，与两步完成后的净差额和成本，不能把未买回当成已降成本。低于摊薄成本卖出后，剩余成本可能上升。

汇总只选择已有完整量化预案，应用复制已校验步骤并本地生成价格/股数主标题；模型文字放入折叠说明。旧报告可继续查看与恢复，但不会补造新预案，需重新分析生成带量化字段的新报告。

本轮本地验证：512项前端测试通过；110项Rust测试通过，12项额外网络/保存样本测试默认忽略。真实Vue组件桌面与390px窄屏验收通过，含报告删除、恢复及折叠状态；两轮授权Flash→Pro模型流程均完成，独立输出各修复一次后通过，汇总均通过。原始输出、修复输出与冻结快照保存在私有临时目录，验收只读账户数据库。保存的两轮报告还用最终校验代码离线回放通过。截图采用标明虚构的QA数据。

最终约束版本又完成一轮真实Flash→Pro验收：独立请求74.2秒、一次字段格式修复67.1秒、汇总36.6秒，全部最终校验通过。三轮候选版验收中均发生一次冲突字段格式修复，不能声称首次输出全部通过或格式错误已绝对消除；应用最多修复一次并分别保留原始与修复输出。
