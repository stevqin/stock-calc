# 卖出盈亏文案与屏幕阅读器适配清理设计

日期：2026-10-10

## 背景

项目目前在账户概况、证券列表、盈亏分析、历史记录预览和说明文档中使用“已实现盈亏”“历史已实现”“FIFO 已实现”等表达。该指标实际在每笔卖出发生时确认，不要求证券已经全部清仓，因此“已实现”容易被理解为“已清仓”。

项目同时存在大量显式屏幕阅读器适配，包括 `aria-*` 属性、显式 `role`、隐藏朗读文本和第三方日期组件的 ARIA 配置。产品决定移除这一层适配，同时保留普通用户使用的键盘操作、焦点行为和原生 HTML 结构。

## 目标

1. 用户看到指标名称时，可以直接理解它代表卖出交易已经确认的盈亏，并且包含部分卖出与全部清仓。
2. “清仓”只描述持仓数量归零并结束的完整持仓轮次。
3. 项目自身的源代码、测试和 QA 页面不再包含显式屏幕阅读器专用适配。
4. 删除适配后，现有鼠标操作、键盘快捷操作、焦点管理、视觉状态和业务计算保持正常。

## 盈亏术语

内部模型继续使用 `realized` 字段，数据库结构、计算公式和历史账户数据均不变。只调整用户可见文案、提示、测试描述和项目文档。

统一使用以下表达：

| 当前表达 | 新表达 | 使用位置 |
| --- | --- | --- |
| 累计已实现 · FIFO、累计 FIFO 已实现 | 累计卖出盈亏（FIFO） | 账户概况、证券详情、历史重算预览 |
| 已实现 · FIFO、历史已实现 | 历史卖出盈亏 | 持仓表、自选表和贡献拆分 |
| 已实现盈亏 | 区间卖出盈亏 | 盈亏分析的区间汇总 |
| 已实现、已实现盈亏 | 区间卖出盈亏、当日卖出盈亏 | 区间证券贡献、日期详情 |
| FIFO 已实现收益 | FIFO 卖出盈亏 | 做 T 配对说明及相关帮助文字 |

统一解释为：

> 卖出盈亏＝卖出净收入−按 FIFO 匹配的买入成本，包含部分卖出和已经清仓的交易。

“浮动盈亏”继续表示当前剩余 FIFO 持仓按现价计算的未确认盈亏。“清仓盈亏”“完整轮次”只用于持仓数量归零后的胜率、平均盈利和平均亏损统计。

README、当前功能说明、历史发布说明、验证记录与测试名称中的相同术语一并更新，避免在仓库内继续出现会误导读者的旧表达。

## 屏幕阅读器适配清理范围

从项目维护的源代码、测试和 QA 页面中删除：

- 所有静态和动态 `aria-*` 属性，包括 `aria-label`、`aria-selected`、`aria-pressed`、`aria-expanded`、`aria-current`、`aria-invalid`、`aria-live`、`aria-hidden`、`aria-controls`、`aria-describedby` 等；
- 所有显式 `role` 属性，包括 dialog、alert、status、tab、tabpanel、menu、menuitem、img、scrollbar、combobox、listbox、option 和 group；
- `.sr-only` 等只供朗读、视觉上隐藏的文本节点与样式；
- 项目组件向第三方控件传递的 ARIA 配置，例如日期时间组件的 `aria-labels`；
- 仅用于生成、同步或查询上述属性的代码。

以下内容保留：

- 可见的 `<label>`、按钮文字、字段标题和 `title` 悬浮提示；
- `Esc` 关闭、方向键调节和列表键盘导航；
- 弹窗焦点锁定、打开时聚焦、关闭后恢复焦点；
- `:focus-visible` 等视觉焦点反馈；
- 原生 `button`、`input`、`select`、`table`、`dialog` 等 HTML 元素及其默认语义；
- 为业务逻辑所需的 `tabindex`、`autofocus` 和键盘事件。

## 状态与测试定位迁移

部分样式、交互代码和测试目前把 ARIA 属性同时当作程序状态或选择器。删除属性时按下列规则迁移：

- 视觉状态改用已有的 `.active`、`.selected`、`.invalid` 等 class；缺少时增加明确的普通 class 或 `data-state`。
- 输入校验由 `aria-invalid` 改为 `.invalid` 或 `data-invalid`，保持错误边框与校验逻辑不变。
- 列表当前项由 `aria-selected` 改为 `.active`，键盘定位查询同步修改。
- 测试优先使用可见文字、现有 class 和组件 props；无法稳定定位的控件增加 `data-testid`。测试属性不承载用户文案或产品状态。
- QA 示例中的 ARIA 和显式 role 同步删除，避免示例重新引入旧模式。

## 代码范围

预计修改：

- `src/*.vue`、`src/components/*.vue` 中的模板、交互查询和相关样式；
- `src/*.css`、`src/components` 样式中依赖 ARIA 状态的选择器；
- `src/**/*.test.ts` 中依赖 ARIA 或 role 定位的测试；
- `qa/` 中的示例页面；
- README、盈亏分析说明、发布说明和验证记录中的盈亏术语。

不修改：

- FIFO 账本算法和 `realized` 内部字段；
- SQLite 数据结构、账户文件格式和迁移逻辑；
- 键盘、焦点、鼠标及触控行为本身；
- 第三方依赖包内部代码。

## 验证

1. 新增或调整术语测试，覆盖账户累计、证券历史、区间和当日四个上下文。
2. 调整组件测试的元素定位方式，并运行完整 Vitest 测试集。
3. 运行 Rust 测试、TypeScript 类型检查和生产构建，确认数据契约未受影响。
4. 对 `src/`、`qa/` 和入口文件执行静态扫描，确保不存在 `aria-*`、显式 `role`、`ariaLabel`、`aria-labels` 或 `.sr-only`。
5. 手工预览主窗口、交易弹窗、盈亏分析、证券搜索、右键菜单、日期控件和菜单栏弹窗，确认视觉状态与交互未因选择器迁移而变化。
